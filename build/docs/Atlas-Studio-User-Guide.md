# Atlas Studio 0.1.0 — complete user guide

An offline, task-based guide to the available features. Press **F1** in Atlas, or choose **Atlas Studio menu → Help & Learning**, for searchable lessons and guided tours. 47 lessons and 10 tours are included.

The app supports any writing subject. Templates/layouts are optional starting points. Optional local speech recognition and OCR do not write or rewrite for you. No account or subscription is required.

## Using the tours

Choose Guided tours in the learning center. Start with Quick start, select a topic tour, or follow Complete feature tour. Use Back/Next, expand Follow the steps, and choose Open this feature when you are ready to try the controls. Pause or close the tour to save your place; Resume tour continues there later. Finish marks that tour complete. Tours never automatically edit documents, start a microphone or choose files.

Create practice project adds separate sample writing and linked cards. Reusing the button reopens the existing practice project without resetting your edits. New practice material does not replace existing projects. Mark as learned/unread keeps a local reading checklist.

## Start here

<a id="welcome"></a>

### Your first session

Choose a starting point for any kind of writing.

**Where:** First launch; Atlas Studio menu → Help & Learning

1. Choose A fresh page for an empty project, Show me around for a practice project and quick tour, or Continue with my existing library when that option appears.
2. Use New to create ordinary editable writing. You can write fiction, fan fiction, an article, an essay, a letter, poetry, research or another kind of text in the same project.
3. Open Help & Learning whenever you need instructions. Choose a short tour, resume a paused one, or search for the task you want to do.
4. For hands-on learning, choose Create practice project in this center. It adds separate sample material and never resets your existing work.

**What you should see:** You have a place to write and can choose how much guidance to see.

**Helpful details**

- Templates suggest a starting structure; they never restrict your subject or audience.
- Replaying a tour does not create another project. The practice-project button reopens its existing project if it is still present.

<a id="workspace"></a>

### Find your way around

Understand the title bar, sidebar, main area and optional panels.

**Where:** The main Atlas window

1. Use the Atlas Studio name/logo at the top left to open the application menu. It contains import, library, backup, preferences and help actions.
2. Choose a project or document in the left sidebar. The main area displays your writing or the selected workspace view.
3. Use Back and Forward above the workspace, Alt Left/Right, or mouse navigation buttons to revisit locations. Recent locations offers the last 20 distinct entries from this session. Opening another library resets the navigation history.
4. Use the top toolbar for Writing tools, search, focus, details, Export and New. Hover an icon for its name; keyboard focus also reveals an outline.
5. Open the details panel only when needed. Drag the sidebar separator to resize it, or focus the separator and use arrow keys. Preferences retain your panel choices.
6. Use the window controls to minimize, maximize/restore or close Atlas. Closing waits for saving; if saving fails, Atlas offers ways to keep or rescue your draft.

**What you should see:** One sidebar and one main work area keep navigation predictable.

**Helpful details**

- The project name in the title bar tells you where you are.
- F1 opens this guide; Ctrl K searches the library.

<a id="views"></a>

### Choose a workspace view

Use different perspectives on the same writing and notes.

**Where:** Workspace view menu, at the top left below the title bar

1. Open Workspace view. The menu groups Writing, Knowledge cards and Manuscript; Board, Connections and Timeline; then Research shelf, Writing goals and Link health.
2. Choose a view with the pointer, or move with arrow keys, Home and End and activate with Enter. Escape closes the menu; Tab continues to the next toolbar control.
3. Return to Writing whenever you want to edit the original item. A stage, date or relationship changed in another view belongs to that same item.
4. Use only the views that help your current work; you do not need to fill every board or diagram.

**What you should see:** Planning and research stay connected to the draft.

**Helpful details**

- Changing views does not create copies of your documents.

<a id="projects"></a>

### Projects and library folders

Create, select and locate your work.

**Where:** Projects in the sidebar; Atlas Studio menu → Choose library folder

1. Use the plus button beside Projects to create a project. Give it a name, color and optional writing intention/deadline, then save.
2. Select its name to limit the workspace to that project, or choose All projects to see writing across the library.
3. Edit a project through its sidebar controls. Document details can change the project for an item and its descendants.
4. For a different library on disk, use Choose library folder. Save current work first and select the intended folder. Preferences → Open library folder shows the current location.

**What you should see:** Projects group related writing; a library is the on-disk collection containing all those projects.

**Helpful details**

- Project folders in the tree are organizational items inside a project, not Windows directories.
- Existing installations normally retain the legacy %APPDATA%\Folio Studio location.

**Format notes and limits**

- Use one Atlas instance to write a given library. Library files are local and are not encrypted by Atlas.

<a id="create"></a>

### Create a document or card

Start blank or use an editable template.

**Where:** New button; Ctrl N; Ctrl Shift N for a card

1. Select the project, then choose New. Enter a title and choose the kind: Document, chapter, scene, section, folder or knowledge card.
2. Choose Blank document or an optional starter from the template groups. Your own saved document templates appear under Your templates.
3. Choose Place inside when you want nested writing. Creating from a folder or chapter row menu preselects that parent.
4. Create the item and write. Change the title directly above the editor. Use Document options to duplicate it, convert it between writing/card, save a checkpoint or move it to trash.

**What you should see:** You have an ordinary editable item with a stable identity.

**Helpful details**

- A folder holds other items and has no draft text.
- Move nested contents elsewhere before converting their parent into a card.

## Writing & review

<a id="tabs"></a>

### Document tabs and reading memory

Switch drafts without losing your place.

**Where:** Tab strip above Writing

1. Open a document from the sidebar or search. It appears in the tab strip; selecting a tab returns to that document.
2. Hover or focus a tab to reveal its pin and close buttons. Pinned tabs stay first; a tooltip includes the project when titles match.
3. Close a tab with its X or Ctrl W. Use the reopen-arrow button or Ctrl Shift T to reopen a recently closed tab. Closing a tab does not delete the document.
4. Use Ctrl Tab / Ctrl Shift Tab to cycle tabs. On a focused tab, arrow keys, Home and End move between them.
5. Return to a draft to restore cursor/selection and scroll. The PDF reader remembers its own page and zoom.

**What you should see:** You can move between drafts and sources while keeping your position.

**Helpful details**

- The sidebar pin/filter is a bookmark for writing; tab pinning controls the open tab strip.

<a id="format"></a>

### Writing and selection formatting

Format a passage without a crowded permanent ribbon.

**Where:** Writing editor; toolbar near selected text

1. Choose Outline in the editor toolbar to show headings. Select a heading to place the cursor there. A warning marks skipped heading levels. Collapse hides descendant headings in the outline, without hiding or changing the writing.
2. Hover or focus an outline row for Move up/down controls. A move includes its text, images and all subsections, and can be undone in one step. Moves stay among sibling headings; headings nested inside tables or lists cannot be moved here.
3. Click the draft and type. Select a passage to reveal bold, italic, underline, highlight, comment, link and list controls beside it.
4. Use Paragraph style above the editor for paragraph or heading levels 1–3. Headings also build the outline in document details.
5. Use Insert for bullet/numbered lists, checklists, quotes, code blocks, dividers, tables, images, links and equations.
6. Use Ctrl B / Ctrl I for common formatting and the undo/redo buttons for editor changes. Word and character counts appear below the draft.
7. Right-click a misspelled word for local suggestions or Add to personal dictionary. Set the language in Language & accessibility.

**What you should see:** Your draft has readable structure with formatting close to the text.

**Helpful details**

- Blank writing remains unrestricted across purposes.
- Word segmentation varies by language, so treat counts as a writing aid rather than linguistic certification.

<a id="tables"></a>

### Tables and checklists

Keep structured information inside the draft.

**Where:** Writing → Insert; Table options while inside a table

1. Place the cursor where the table belongs, choose Insert → Table, and type in its cells.
2. Click inside a cell to reveal Table options. Add a row below or column to the right, remove the current row/column, or remove the table.
3. Drag a column boundary to adjust its width. Review complex tables after export because printed page widths differ.
4. For tasks, use Insert → Checklist. Enter each item and toggle its checkbox as the work progresses.

**What you should see:** Tables and tasks remain editable in the document.

**Helpful details**

- Save before experimenting with a large structural change; editor undo can help reverse an accidental edit.

<a id="images"></a>

### Images and web links

Bring local illustrations and external references into your writing.

**Where:** Writing → Insert → Image or Link

1. For an image, choose Insert → Image, add a local file if needed, then select its thumbnail. Atlas stores the research attachment with the library.
2. Keep meaningful filenames so images are easy to identify on the research shelf. Complete backups include the stored bytes.
3. For a web link, select text and choose Link, or supply an optional label for a new link. Use an https://, http:// or mailto: address.
4. Ctrl-click a web link to open it in your system browser. For another Atlas item, choose Link a note instead to keep a stable internal connection.

**What you should see:** Images and links support the writing while remaining locally organized.

**Helpful details**

- Word imports can retain embedded images.

**Format notes and limits**

- External websites open separately and may require a network. Word uses a placeholder for WebP; supported raster images export normally.

<a id="equations"></a>

### Equations and technical text

Add rendered math and readable code examples.

**Where:** Writing → Insert → Equation or Code block

1. Place the cursor, choose Equation, and enter the LaTeX expression. Check the live preview before inserting it.
2. Use standard supported KaTeX syntax. Correct the expression if the preview shows an error.
3. For code examples, use a code block. Treat it as readable text, not an executable program.
4. Check your intended export: HTML/PDF render equations, while Word keeps visible editable LaTeX text.

**What you should see:** Technical material can sit alongside ordinary prose.

**Helpful details**

- A Technical writing layout is also available.

**Format notes and limits**

- Atlas does not compile complete TeX projects, execute code or generate native Word math objects.

<a id="find"></a>

### Find and replace in one document

Locate a word and revise individual or repeated occurrences.

**Where:** Ctrl F; Find and replace toolbar button

1. Open the document and press Ctrl F. Enter Find text and, if needed, Replacement text.
2. Choose Match case when capitalization should matter. Next match selects the first occurrence, then advances through the document.
3. Use Replace for the current occurrence or Replace all for every match in this document.
4. Review the draft and save. For selected documents across a project, use Find & replace across writing instead.

**What you should see:** A focused replacement changes only the current document.

**Helpful details**

- The search is literal text; it is not a regular-expression editor.

<a id="focus"></a>

### Focus mode and comfortable typography

Give the draft more room when you need fewer controls.

**Where:** Focus mode in the top toolbar; Preferences

1. Open the draft, then choose Focus mode. The surrounding navigation is reduced so the writing has more space.
2. Press Escape to return to the normal workspace.
3. In Preferences, choose the normal writing font and text size. Standard layout follows these preferences.
4. Use Writing layout for a document-specific size/spacing override; use Language & accessibility for scaling the entire interface.

**What you should see:** You can reduce visual distractions without changing the document’s content.

**Helpful details**

- Use reduced motion if transitions distract you.

<a id="layouts"></a>

### Poetry, script, letter and technical layouts

Choose a helpful starting layout without locking your writing to a genre.

**Where:** Writing tools → Writing layout

1. Open a writing document and choose Standard, Poetry, Script draft, Letter or Technical.
2. Adjust the document writing size and line height when the preset needs refinement.
3. Continue editing freely; the layout does not impose a mandatory subject, structure or audience.
4. Use Standard to return to your usual writing typography. Choose print/export settings separately in Export presets.

**What you should see:** The editor fits the current piece while leaving the text unrestricted.

**Helpful details**

- Poetry can use deliberate line breaks; imported Unicode prose remains ordinary text.

**Format notes and limits**

- Script draft is a drafting aid, not industry screenplay pagination. Advanced visual poetry and exact print composition remain manual.

<a id="comments"></a>

### Comments and annotations

Keep revision notes beside a passage.

**Where:** Selected-text comment button; Ctrl Alt M; Writing tools → Comments & annotations

1. Select the passage before opening Comments if you want an anchored note. Without a selection, the comment applies to the document generally.
2. Type Your comment and choose Add comment. The comment text is stored separately from the draft.
3. Keep writing with the optional comment panel beside the editor. Selecting a saved quotation scrolls to its anchor when that anchor still exists.
4. Resolve finished notes; enable Show resolved comments to reopen them. Delete comment removes the note and its matching anchor.

**What you should see:** Revision reminders remain connected without becoming part of your prose.

**Helpful details**

- Deleting or substantially replacing an anchored passage may remove its visible anchor; the saved comment/quotation can still help you find context.

**Format notes and limits**

- Comments are retained in Atlas backups; exports do not create native Word review-comment objects.

<a id="revisions"></a>

### Revision history and passage comparisons

Keep checkpoints and restore only the writing you need.

**Where:** Document options → Save revision checkpoint; Writing tools → Compare revisions

1. Before a major rewrite, save a revision checkpoint from Document options. Revision history also provides Checkpoint now and earlier saved drafts.
2. Open Compare revisions and choose Earlier draft. Read the highlighted word changes and the earlier/current passage blocks.
3. Choose Restore this passage for the block you want back. Atlas checkpoints the current draft first so the newer writing remains in history.
4. For a whole earlier draft, open Revision history, review its preview and use its restore action.
5. Check the resulting writing before continuing. Up to 60 checkpoints are retained per document.

**What you should see:** You can recover earlier writing while preserving the newer checkpoint.

**Helpful details**

- A separate complete backup protects the whole library, not only one draft.

**Format notes and limits**

- Passage restoration works with paragraph/content blocks, not arbitrary character-range merge editing.

<a id="compare"></a>

### Edit two documents side by side

Keep another draft visible while working.

**Where:** Compare two documents above the draft

1. Open the main document, then choose Compare two documents.
2. Select the second document. Its editor appears beside the primary draft; edits belong to the document shown in that pane.
3. Use the close-comparison control to return to one draft.
4. For automatic change highlighting between versions of one document, use Compare revisions instead.

**What you should see:** Two editable documents can share the writing area.

**Helpful details**

- Close a research/comment panel when you need the extra width.

<a id="dictation"></a>

### Free offline speech-to-text

Turn your voice or a local recording into text, then review before insertion.

**Where:** Ctrl Shift D; Writing tools → Offline dictation

1. Open a writing document and Offline dictation. Choose the spoken language or Detect automatically.
2. Choose Start recording only when you want microphone capture. Stop & transcribe ends capture and runs the bundled local speech model.
3. Alternatively, choose Transcribe audio file and select a supported local recording. Keep it under 100 MB and five minutes after decoding.
4. Review and correct the transcript. Place the writing cursor and choose Insert reviewed transcript. You can continue typing while transcription runs.
5. Use Cancel transcription if needed. Advanced can import a compatible Whisper GGML model for another speed/accuracy tradeoff.

**What you should see:** Speech becomes reviewed text in your draft with no account or per-use fee.

**Helpful details**

- The full installer bundles multilingual Whisper Small Q5 and a CPU runtime. Recognition is optional; there is no AI writing or rewriting.
- Recording starts only with Start. Temporary native input/output files are removed after the job; a crash may leave SpeechTemp files locally.

**Format notes and limits**

- Recordings are limited to five minutes. Closing the panel stops/cancels its job; uninserted review text is temporary. Recognition may make mistakes. Microphone access depends on your Windows device/privacy settings.

## Organize your work

<a id="folders"></a>

### Folders, chapters and scenes

Build a nested structure and arrange it in the order you need.

**Where:** Sidebar item menu; document details → Parent section

1. Use a row’s menu to create a folder, chapter or scene inside it. Expand/collapse arrows reveal or hide the children.
2. Drag an item to reorder within its project. Hold Shift during the drag to place it inside another suitable item.
3. For a precise destination, use Move to… in the row menu or Parent section in document details. A parent cannot be inside its own descendants; a card cannot contain nested writing.
4. Open a folder to see its contents and breadcrumbs. Moving a chapter/folder carries its descendants while their document IDs remain unchanged.
5. Use Manuscript’s reorder controls as a keyboard alternative. Check the resulting outline before exporting.

**What you should see:** Your nested outline controls reading and collected export order.

**Helpful details**

- Pinned filters retain the parent path to pinned writing.
- Use the bulk tool for selected items across a larger move.

<a id="bulk"></a>

### Organize several items together

Move, tag, archive, restore or export a selection.

**Where:** Writing tools → Organize selected items

1. Choose the project and select the items you want to organize. Review the selection before applying an action.
2. Choose the Bulk action. Move uses a destination; tagging uses the supplied tags; archive hides selected work from ordinary views without trashing it.
3. Apply to selection. Folder/subtree actions include descendants, and invalid destinations inside the selection are rejected.
4. To bring archived work back, enable Show archived items, select it and choose restore. Restoring nested writing also restores its archived parent path.
5. Choose export to open export options for the selection. Folder containers are omitted from the actual writing output.

**What you should see:** Related items can be managed consistently in one operation.

**Helpful details**

- Use status:archived in Ctrl K to locate archived writing.
- Archive and trash are separate states.

**Format notes and limits**

- Advanced clipboard cut/paste and a complete tree keyboard-command system are not included.

<a id="batch-replace"></a>

### Preview project-wide replacements

Apply one carefully reviewed change across chosen writing.

**Where:** Writing tools → Find & replace across writing

1. Choose the project and documents to include. Enter the literal find and replacement text, with Match case if appropriate.
2. Preview the changes. Review the matching document names, occurrence counts and before/after text.
3. Apply the batch only when the preview is correct. The operation changes the selected documents together.
4. Use the saved operation’s Undo when necessary. Atlas refuses that undo if a later edit changed the affected documents, protecting newer writing.

**What you should see:** A project-wide change has a review step and a guarded recovery path.

**Helpful details**

- Generated citations, bibliography text, note bodies and code are excluded.
- Up to ten batch snapshots are retained. Make a full backup before a very large revision.

<a id="templates"></a>

### Reusable project and document templates

Save your own structures and starting text.

**Where:** Writing tools → Your reusable templates

1. For a project template, choose a project and Template name. Enable Include starter text and notes only if you want content copied along with the structure.
2. Choose Save project structure. Later, Create project makes a new editable project with fresh IDs and remapped internal links.
3. For a document template, open the desired draft, name the template and choose Save current document template.
4. Use New → Start with → Your templates to create a document from that starter. Remove templates from the tool when you no longer want to offer them.

**What you should see:** Your preferred organization can be reused without copying document identities.

**Helpful details**

- Deleting a template does not delete documents or projects already created from it.
- Built-in starter groups cover 25 optional structures for varied writing purposes.

<a id="properties"></a>

### Details, tags and custom properties

Describe writing with only the fields you need.

**Where:** Document details; Writing tools → Custom document properties

1. Open document details for project, kind, parent, status, date, tags, outline and related links. Adjust the panel width if needed.
2. Use tags consistently; hierarchical tags such as research/history can help group related material. Sidebar filters narrow the current workspace.
3. Open Custom document properties to add optional text, date or number fields, such as viewpoint, audience, revision deadline or publication status.
4. Name each field clearly and enter its value. These custom values are included in library search.
5. Remove fields you no longer need. Properties are descriptive metadata; the writing remains unrestricted.

**What you should see:** Your metadata supports organization without making every draft a complex form.

**Helpful details**

- Parent changes preserve item identities.

**Format notes and limits**

- Custom fields are per document and do not provide database formulas or relational field types.

<a id="capture"></a>

### Quick capture and Inbox

Save a loose idea before deciding where it belongs.

**Where:** Writing tools → Quick capture

1. Open Quick capture and enter a short Capture title and the idea text.
2. Choose Save to inbox. Atlas creates or reuses an Inbox project and saves a normal editable document there.
3. Select the captured item to open it. Expand it, add tags or link it to related writing.
4. Use document details or the bulk tool to move it into its eventual project/parent when you are ready.

**What you should see:** Ideas have a dependable holding place that is easy to reorganize later.

**Helpful details**

- Capture is inside Atlas; it is not a global Windows hotkey or browser clipper.

<a id="cards"></a>

### Knowledge cards and categories

Keep notes, characters, locations, concepts and research near the draft.

**Where:** Workspace view → Knowledge cards; Ctrl Shift N

1. Create a knowledge card with New or Ctrl Shift N. Give it a useful title and editable content.
2. Use the card’s category/tags and properties to distinguish a character, location, concept, source note or another kind of idea.
3. Browse cards in Knowledge cards, or enable Show knowledge cards in the writing sidebar.
4. Link a card to relevant writing and review its backlinks. A card is the same saved item across the writing, board and connection views.

**What you should see:** Small pieces of knowledge can connect to longer writing without being duplicated.

**Helpful details**

- A card does not contain nested writing. Use a folder or chapter for a hierarchy.

<a id="search"></a>

### One search across the library

Find writing, cards, projects, events, references and indexed source pages.

**Where:** Ctrl K; Find anything button

1. Press Ctrl K and enter words or a quoted phrase. Search includes writing text, titles, tags, custom properties and other library items.
2. Narrow the results with filters such as type:card, type:file, type:reference, type:source-page, status:ready, tag:research or project:"My project".
3. Use arrow keys to select a result and Enter to open it. Pointer selection works too.
4. Use status:archived to find archived writing. For PDF page contents, index the source first in Search research contents.
5. Press Escape to close search and return to the draft. Inside Help & Learning, Ctrl K or Ctrl F searches guide lessons instead.

**What you should see:** You can reach the same saved item from one search entry point.

**Helpful details**

- Ctrl N creates a document; Ctrl Shift N creates a card. Quick commands are limited to the actions exposed by the current UI.

## Plan & connect

<a id="links"></a>

### Stable links, backlinks and link health

Connect ideas and resolve unclear connections.

**Where:** Insert → Link → Link a note instead; Workspace view → Link health

1. To make a stable internal link, use Link a note instead and choose the intended item. Atlas stores its ID so a rename does not break that connection.
2. You can also type [[Note title]]. An unambiguous project-local title takes priority over matches elsewhere.
3. Open document details to inspect backlinks and related notes. Renaming an unambiguous linked note updates connected title references.
4. Open Link health to find missing or ambiguous wiki links. Pick the intended existing item, clarify the title, or use the offered create-card action for a missing note.

**What you should see:** Connections remain useful as your library changes.

**Helpful details**

- Use distinct titles when relying on typed wiki links; ID links are the most reliable choice when titles repeat.

<a id="board"></a>

### Board and drafting stages

Track work from idea through completion.

**Where:** Workspace view → Board

1. Open Board for the current project. Cards represent the same writing items shown elsewhere.
2. Drag a card between stages as the work moves forward. You can also set the item’s stage in document details.
3. Open a card to return to its writing. The changed stage is immediately visible in the same item’s metadata.
4. Use the board for your own process; it does not require a particular genre or publication workflow.

**What you should see:** A simple stage overview supports drafting and revision.

**Helpful details**

- Folder containers are omitted from the board.

<a id="graph"></a>

### Connections graph

Explore relationships without changing the underlying writing.

**Where:** Workspace view → Connections

1. Create internal links between writing and cards, then open Connections to see related nodes and edges.
2. Open a node to return to its writing. Drag nodes to arrange the graph; Atlas remembers those positions.
3. Use the graph’s zoom and reset/layout controls when the arrangement becomes hard to read.
4. For a large library, load additional batches as offered. Focus on a project or smaller collection when you want a clearer map.

**What you should see:** The graph helps you discover context among your saved links.

**Helpful details**

- Large graphs load progressively rather than drawing the whole library at once.

<a id="timeline"></a>

### Timeline, events and milestones

Arrange dates alongside your writing.

**Where:** Workspace view → Timeline

1. Open Timeline and choose a lane/filter if needed. Dated writing and separate events can share this view.
2. Use New event to enter a title, date, description and optional lane. Open an existing event to revise those details.
3. Give a writing item a date through document details when it belongs on the timeline. Use the undated-writing controls to schedule items when offered.
4. Move an unwanted event to trash and restore it through Atlas Studio menu → Trash if needed. Document and event recovery are both supported.

**What you should see:** Dates and milestones become part of the same project context.

**Helpful details**

- A separate event describes a milestone without requiring a writing document.

<a id="manuscript"></a>

### Manuscript builder and read-through

Read and export longer work in the order you arranged.

**Where:** Workspace view → Manuscript

1. Arrange chapters, scenes and sections in the project tree. Expand the nested outline in Manuscript.
2. Use drag ordering or the up/down controls to refine the sequence. Folder containers group content without adding empty chapter text.
3. Choose Read through to read the collected manuscript continuously. Open an individual item when you want to edit it.
4. Export in manuscript order, or choose only selected chapters. Check the outline and export preview/options before saving the file.

**What you should see:** Your reading order and collected export order agree.

**Helpful details**

- Different kinds of writing can use the same nested structure: report sections, essay parts or book chapters.

<a id="goals"></a>

### Writing goals and activity

Use optional intentions without turning writing into a requirement.

**Where:** Workspace view → Writing goals; Preferences

1. Set the daily writing intention in Preferences and project intentions/deadlines when editing the project.
2. Open Writing goals to review the project and daily activity tracked from saved writing.
3. Use the numbers as a guide and adjust the intention to suit the work. Research and revision are valuable even when they add few words.
4. Keep imported prose separate from newly written activity; Atlas does not count an Atlas import as new writing.

**What you should see:** Progress information stays available when it helps.

**Helpful details**

- Counts are an activity aid, not a promise of exact linguistic segmentation or work measurement.

## Research & references

<a id="research"></a>

### Research shelf and source files

Collect documents, images, sources and reading notes.

**Where:** Workspace view → Research shelf

1. Choose Add files and select local PDFs, images or supported text files. Atlas stores a library copy so the project can include it in backups.
2. Open a source from the shelf. A PDF can appear beside your writing; image and text previews remain available for other supported files.
3. Add reading notes, references and related cards. Meaningful names make later search easier.
4. Use Search research contents to build a page-text/OCR index when you need content search, rather than only filename and notes search.

**What you should see:** The source material remains close to the writing it supports.

**Helpful details**

- Changing an original file outside Atlas does not automatically replace or reindex the stored library copy.

<a id="pdf"></a>

### Read, highlight and extract from PDFs

Return to the exact source page behind a note.

**Where:** Research shelf → open a PDF

1. Open the PDF beside a draft. Use Previous/Next, PDF page and the zoom controls to find the passage.
2. Select text in a selectable PDF and choose Highlight selected text. Save any highlight comment or reading note you need.
3. Use Extract to card for a source-linked note. The new card retains the source ID/page and a link back to that page.
4. Select the saved source link later to reopen the file at the referenced page. Close the reader to regain writing space; page/zoom are remembered.

**What you should see:** Reading notes and highlights keep their source context.

**Helpful details**

- Scanned pages may need OCR for search, but OCR does not create a selectable PDF text layer for the reader.

<a id="ocr"></a>

### Search PDF contents and use local OCR

Index selectable PDFs and scanned material on this computer.

**Where:** Writing tools → Search research contents

1. Choose a source and Index contents to extract its PDF/text content by page.
2. For scans or images, enable Use local OCR when needed and choose English, French or Arabic data before indexing.
3. Wait for indexing progress. Cancel preserves the previous index and stops after the current page finishes.
4. Search source contents in the tool, or use Ctrl K with type:source-page and your terms. Choose a result to open its exact page.
5. Compare recognized text with the original scan before relying on a quotation or number.

**What you should see:** Research becomes searchable without sending its contents to a service.

**Helpful details**

- OCR is optional local recognition; the original source bytes remain unchanged.

**Format notes and limits**

- OCR can misread text, handwriting, columns or poor scans. It adds searchable index text, not an edited PDF or a selectable reader text layer.

<a id="references"></a>

### Reference records and Zotero imports

Keep bibliography data separate from the draft.

**Where:** Research shelf → references; Import CSL-JSON

1. Use the reference controls to create a record with title, author, year, publisher/journal, DOI and URL.
2. For structured manual author names, use Family, Given; Family, Given. A name without a comma is treated as a literal author label.
3. To import records from Zotero, export a CSL-JSON array there, then choose the reference-import control in Atlas and select that file.
4. Edit or remove reference records from the shelf. After changing cited records, refresh linked references in Citations & notes.

**What you should see:** Consistent source records support reusable citations and bibliographies.

**Helpful details**

- Keep a full backup before removing records that existing writing cites.

**Format notes and limits**

- This is file import, not direct/live Zotero synchronization.

<a id="citations"></a>

### Linked citations and full CSL formatting

Insert citations that retain their source identity.

**Where:** Writing tools → Citations & notes

1. Create/import reference records first, then place the writing cursor where the citation belongs and open Citations & notes.
2. Choose APA, MLA, Chicago notes/bibliography or IEEE. Select the reference(s) and add a locator/page when appropriate.
3. Choose Insert linked citation. Use Insert bibliography to add a linked reference-list block.
4. After changing records or style, choose Refresh linked references. For another style, Import CSL style using an independent .csl file.
5. Review the final publication style and export. Author names, locators and source types affect the result.

**What you should see:** The local citeproc engine formats references without a network service.

**Helpful details**

- Linked citations use reference IDs rather than relying on pasted text.

**Format notes and limits**

- Dependent CSL styles need their parent and are rejected. Chicago note citation text is formatted, but automatic placement into native footnotes is not included; create a semantic note separately when needed.

<a id="notes"></a>

### Footnotes and endnotes

Keep note text as semantic notes with numbered markers.

**Where:** Writing tools → Citations & notes

1. Place the cursor where the note belongs and open Citations & notes.
2. Enter New note text, choose Footnote or Endnote, then Insert note at cursor.
3. Edit existing note text from the note list. Atlas renumbers markers automatically as notes are rearranged.
4. Export to Word when you need actual Word footnote/endnote parts. Check note placement in your target format before publication.

**What you should see:** Notes travel with the writing and remain editable in Atlas.

**Helpful details**

- Footnotes and endnotes have separate numbering.

**Format notes and limits**

- HTML/PDF collect notes at the end, with return links. PDF page-bottom footnote composition is not included. Text formats include note text without print pagination.

## Import & publish

<a id="imports"></a>

### Import writing and an Atlas library

Bring existing work in with a preview where available.

**Where:** Atlas Studio menu → Import documents / Import Atlas library

1. Choose the destination project before importing ordinary documents. Import documents accepts Markdown, plain text, HTML and Word.
2. For an older Atlas library, choose Import Atlas library and select a supported version-1 JSON backup or legacy SQLite database.
3. Review the project/document/event counts and duplicates. Choose to skip identical content/merge matches or import separate copies.
4. Apply the preview, then check the resulting project structure and representative documents. Atlas creates a pre-import safety checkpoint; original Atlas databases open read-only.

**What you should see:** Imported writing becomes editable Atlas items without replacing the current library.

**Helpful details**

- Word imports can retain embedded images.
- A full .folio backup uses Restore a backup copy, not the Atlas JSON/SQLite importer.

**Format notes and limits**

- Browser-only Atlas storage and external media are not imported by the legacy library converter. Complex Word/HTML layout may need review.

<a id="exports"></a>

### Export one draft or collected writing

Save a usable copy in your intended format.

**Where:** Export button; folder export; bulk selected export

1. Open the document/project and choose Export. Choose Current document, All writing in this project/filter, Writing in manuscript order or Selected chapters.
2. For selected writing, tick the intended items. Folder containers are excluded; collected writing follows the arranged outline order.
3. Choose PDF, Word, Markdown, HTML, plain text or EPUB, and select an export layout preset.
4. Choose save location. Once the native picker closes, export runs in the background and you can keep writing.
5. Open the finished file in its target reader and check headings, order, tables, images, notes and equations before sharing it.

**What you should see:** The draft can leave Atlas in a format appropriate to the next step.

**Helpful details**

- HTML/PDF render math and include local media; Word retains common editable formatting/tables/supported images and visible LaTeX text.
- Export options describe output; they do not change the saved draft.

**Format notes and limits**

- EPUB is a text edition, not illustrated/fixed-layout EPUB. Markdown/plain text cannot preserve all rich layout. Exact specialist publishing/prepress composition is not certified.

<a id="presets"></a>

### Save export and print presets

Reuse margins, paper, typography and chapter settings.

**Where:** Writing tools → Export presets

1. Select Standard, Book manuscript, Article, Essay/report or Ebook as a starting point.
2. Adjust page size, font, size, line spacing and margins. Choose chapter numbering/breaks, title page and page numbers where appropriate.
3. Give your custom preset a recognizable name and save it.
4. Select that preset in the export dialog for one document or a collection. Review the exported file before publication.

**What you should see:** Different writing purposes can have reusable output settings.

**Helpful details**

- Writing layout changes the editor; export presets change the output. They are independent.

**Format notes and limits**

- Print-specific pagination applies to PDF/Word/HTML. Plain text and reflowable ebooks do not preserve printed page breaks or page numbers.

## Saving & recovery

<a id="saving"></a>

### Autosave, conflicts and safe closing

Understand whether your latest words are safely on disk.

**Where:** Save status in the title bar; Ctrl S

1. Watch for Unsaved changes, Saving… and Saved locally. Ctrl S asks Atlas to save now.
2. Atlas uses atomic writes and previous-state recovery. Closing waits for saving rather than immediately discarding the current draft.
3. If saving fails, keep the window open. Check storage access/free space, then retry. Use Export draft to rescue writing if necessary.
4. If a conflicting external edit is detected, Atlas rejects the overwrite. Preserve the draft and compare the external library copy before choosing what to keep.
5. For protection beyond one draft or disk, make complete backups and verify a restoration preview.

**What you should see:** The save indicator reflects success, and failure leaves choices for recovery.

**Helpful details**

- Avoid editing library JSON outside Atlas while it is open.
- Revision history, daily checkpoints and full backups serve different purposes.

**Format notes and limits**

- Unexpected OS shutdown/storage failure is not a substitute for a second-drive backup.

<a id="backup"></a>

### Backup health, preview and restoration

Protect the complete library and test the recovery path.

**Where:** Writing tools → Backup & recovery

1. Review missing attachments, free space, revision/daily checkpoint counts and recorded complete backups.
2. The health message identifies missing files, no available complete backup, or an archive older than seven days. Archive availability is not a new integrity check: use Preview a backup to verify its current contents.
3. Choose Create verified backup and save a .folio archive, preferably on a separate drive. It contains writing, events, references, attachments, annotations, history, templates, indexes and imported styles.
4. Choose Preview a backup and select the archive. Atlas verifies it and shows the contents before you commit to restoration.
5. Choose Restore separate copy only when you want to open a new restored library. The current library remains on disk, and the archive is checked again for changes.
6. Review the restored writing and source files. Use Choose library folder when returning to another saved library.

**What you should see:** A portable, verified copy can recover more than the current text document.

**Helpful details**

- Missing attachment bytes cause backup to fail rather than silently omit sources.
- Daily JSON checkpoints refer to the original attachment directory; they are not complete portable archives.

**Format notes and limits**

- Restoration is bounded to 512 MB compressed and 1 GB expanded. Libraries/backups are not encrypted by Atlas.

<a id="trash"></a>

### Trash, restore and archive

Hide or remove work without confusing the recovery options.

**Where:** Atlas Studio menu → Trash; bulk archive controls

1. Use Move to trash on a document, folder or event when you want it out of normal work. Trashing a folder includes its nested writing.
2. Open Trash to see recoverable documents and events, then choose Restore for the item you need back.
3. Restoring a nested item restores the relevant parent path so the item can be reached in the tree.
4. Use archive in Organize selected items for work you want to set aside without putting it in trash. Show archived items or status:archived brings it back into reach.

**What you should see:** Trash and archive provide distinct ways to recover or revisit work.

**Helpful details**

- Closing a tab, deleting a template and hiding a panel are different from trashing writing.

<a id="troubleshooting"></a>

### Troubleshooting and known limits

Choose the right recovery step when something does not behave as expected.

**Where:** Help & Learning; Backup & recovery

1. Cannot find writing? Check the project, sidebar query, pinned/card filters, archive status and Trash before assuming it was lost.
2. Save failure/conflict? Keep the window open, export the draft if needed, check storage access/free space and preserve both versions before resolving an external conflict.
3. No dictation audio? Select the intended Windows input device, allow microphone access for desktop apps, then try a short recording. Audio-file transcription can help distinguish device problems from recognition problems.
4. No source-content results? Index the file first; enable the correct OCR language for a scan. Check the source itself when recognition gets words/numbers wrong.
5. Export looks different? Verify format limits, scope/order and preset. Use Word for native note parts or HTML/PDF for rendered equations; specialist publishing may need another layout application.

**What you should see:** A problem has a concrete next check and a way to protect the writing.

**Helpful details**

- The full installer includes speech/OCR/runtime resources. Reinstall the full package if the speech pack is missing. Uninstall keeps your library.
- For any reported bug, note the app version, action, expected result and actual message without sharing private writing unnecessarily.

**Format notes and limits**

- Maximum validation limits are not demonstrated performance guarantees. Long-session, extreme-size, low-memory, multiple-display and sudden-OS-shutdown testing is incomplete. No live coauthoring, direct Zotero sync, full TeX compiler or app encryption is included.

## Make Atlas yours

<a id="themes"></a>

### Themes, animation and panel preferences

Make Atlas comfortable without adding permanent clutter.

**Where:** Atlas Studio menu → Preferences

1. Choose any of the 15 complete themes. The workspace, menus and optional panels use the same theme colors.
2. Choose your default writing font/size and reduced motion preference. Reduced motion removes decorative transitions.
3. Resize the sidebar with its separator, or use keyboard arrows while it is focused. Adjust the optional details panel width when open.
4. Atlas remembers theme, panel settings, last view/project and writing positions for your next session.

**What you should see:** Appearance and movement suit your own reading comfort.

**Helpful details**

- Use full interface scaling in Language & accessibility when every control needs to be larger.
- Themes: Atlas Midnight, Paper Light, Deep Ocean, Forest, Amethyst, Ember, Graphite, Cobalt, Rose Noir, Parchment, Sage, Open Sky, Lavender, Desert Sand and Quiet Mono.

**Format notes and limits**

- Color contrast has bounded automated checks; every assistive technology/display combination is not certified.

<a id="language"></a>

### Language, RTL and accessibility

Adjust writing direction, spelling and the whole interface.

**Where:** Writing tools → Language & accessibility

1. Set Interface scale from 80–150% for all controls, not only draft text.
2. Choose the default writing direction and, when needed, a direction for the current document. Use Selected paragraph RTL/LTR for a particular paragraph.
3. Choose Local spelling language. Right-click misspelled text for suggestions, or add/remove personal words in the dictionary controls.
4. Use keyboard focus outlines, menu arrows/Home/End, Tab and Escape to navigate. Choose reduced motion in Preferences if needed.
5. Set the dictation language separately; it does not change the spelling dictionary.

**What you should see:** Mixed language work can have appropriate direction and readable controls.

**Helpful details**

- Official dictionaries are bundled for offline use; Windows may also use local native spelling resources.

**Format notes and limits**

- English and French suggestions were tested offline. Not every spelling language, bidirectional export, screen reader or high-DPI configuration is certified.

<a id="shortcuts"></a>

### Keyboard reference

Reach common actions without hunting through menus.

**Where:** Throughout Atlas

1. F1 opens Help & Learning. Inside the guide, Ctrl F or Ctrl K focuses lesson search; Escape closes the center.
2. Ctrl N creates a document; Ctrl Shift N creates a card. Ctrl S saves; Ctrl F finds in the current draft; Ctrl K searches the library.
3. Ctrl W closes a tab; Ctrl Shift T reopens one; Ctrl Tab / Ctrl Shift Tab cycles tabs.
4. Ctrl Alt M opens comments for the selection; Ctrl Shift D opens offline dictation. Ctrl B / Ctrl I format text; editor undo/redo remains available.
5. Use arrow keys/Home/End inside menus and focused tabs, Enter to activate, and Escape to close a menu/dialog or leave focus mode. Use the sidebar separator’s arrow-key controls for width.

**What you should see:** Common actions remain accessible with keyboard navigation.

**Helpful details**

- Help search searches instructions, while the main Ctrl K searches your saved library.
